Especificación de Requerimientos

FinanIA - 50 Requerimientos Funcionales · 25 No Funcionales

Mostrando 50 requerimientos funcionales

🔐 Autenticación y Onboarding 4 RF

▾
RF01El sistema debe permitir el registro de nuevos usuarios con nombre, email y contraseña, validando que el email no esté duplicado y encriptando la contraseña con bcrypt.
RF02El sistema debe permitir el inicio de sesión con email y contraseña, ofreciendo autenticación de dos factores (2FA) y recuperación de contraseña por email.
RF03El sistema debe implementar un onboarding de 6 pasos al registrarse, calculando el perfil de riesgo del usuario (conservador, cauteloso, moderado, valiente, arriesgado) y mostrando una pantalla de bienvenida.
RF04El sistema debe permitir cerrar sesión de forma segura, destruyendo la sesión y redirigiendo al login.

🏦 Cuentas 2 RF

▾
RF05El sistema debe permitir crear, editar y eliminar cuentas (efectivo, ahorros, corriente, tarjeta, inversión) con nombre, saldo inicial y etiqueta personalizada.
RF06El sistema debe calcular automáticamente el saldo actual de cada cuenta y mostrar el saldo consolidado de todas las cuentas.

💸 Transacciones 4 RF

▾
RF07El sistema debe permitir registrar ingresos y gastos con monto, fecha, categoría, cuenta, descripción y método de pago, marcando transacciones como recurrentes.
RF08El sistema debe permitir importar transacciones desde archivos CSV, detectando automáticamente las columnas de fecha, monto y descripción, y categorizando automáticamente según palabras clave.
RF09El sistema debe permitir editar y eliminar transacciones, filtrarlas por tipo (ingreso/gasto) y buscarlas por descripción o categoría.
RF10El sistema debe filtrar dinámicamente las categorías según el tipo de transacción seleccionado (JavaScript).

🏷️ Categorías 2 RF

▾
RF11El sistema debe permitir crear, editar y eliminar categorías de ingreso y gasto, personalizando color e ícono.
RF12El sistema debe proteger la eliminación de categorías que tengan transacciones o presupuestos asociados.

🎯 Metas y Aportes 3 RF

▾
RF13El sistema debe permitir crear, editar y eliminar metas con nombre, monto objetivo, fecha límite y barra de progreso visual.
RF14El sistema debe permitir registrar aportes a las metas, manteniendo un historial editable y eliminable, y recalculando el progreso automáticamente.
RF15El sistema debe calcular automáticamente el fondo de emergencia recomendado (3-6 meses de gastos).

💳 Deudas y Pagos 3 RF

▾
RF16El sistema debe permitir registrar, editar y eliminar deudas con acreedor, monto, tasa de interés, vencimiento y pago mínimo, calculando el interés compuesto.
RF17El sistema debe alertar si una deuda supera la tasa de usura (28.79% EA) y generar un calendario de pagos con alertas 7 días antes del vencimiento.
RF18El sistema debe permitir registrar pagos parciales o totales a las deudas, manteniendo un historial editable y recalculando el saldo pendiente.

📅 Presupuestos 2 RF

▾
RF19El sistema debe permitir crear, editar y eliminar presupuestos mensuales por categoría, comparando el presupuesto con el gasto real.
RF20El sistema debe generar alertas automáticas al 80% y 100% del presupuesto por categoría.

💼 Fuentes de Ingreso 2 RF

▾
RF21El sistema debe permitir registrar fuentes de ingreso con tipo y frecuencia, calculando la estabilidad de los ingresos (0-100%).
RF22El sistema debe proyectar los ingresos futuros basándose en el historial de las fuentes de ingreso.

🔄 Recurrentes 2 RF

▾
RF23El sistema debe agrupar las transacciones recurrentes y mostrar su impacto mensual y anual.
RF24El sistema debe detectar automáticamente posibles suscripciones (gastos repetidos pequeños) y mostrarlas agrupadas.

📈 Reportes 2 RF

▾
RF25El sistema debe generar reportes con filtro por rango de fechas, mostrando gráficas de ingresos vs gastos, gastos por categoría y top 5 de gastos más altos.
RF26El sistema debe permitir exportar los reportes a PDF.

📅 Calendario 2 RF

▾
RF27El sistema debe mostrar una vista de calendario mensual con las transacciones, vencimientos de deudas y metas.
RF28El sistema debe proyectar las transacciones recurrentes en los próximos meses y mostrar el detalle de cada día al hacer clic.

🔍 Búsqueda Global 1 RF

▾
RF29El sistema debe permitir buscar en todo el sistema con Ctrl+K, mostrando resultados agrupados por tipo (transacciones, metas, deudas, cuentas, categorías, productos) y permitiendo navegar con flechas y Enter.

🏆 Salud Financiera 1 RF

▾
RF30El sistema debe calcular un puntaje de salud financiera (0-100) evaluando 5 componentes: fondo de emergencia, nivel de deuda, tasa de ahorro, diversificación y estabilidad, mostrando el desglose con recomendaciones.

🏅 Logros 1 RF

▾
RF31El sistema debe otorgar logros automáticamente al cumplir hitos, mostrando los logros desbloqueados, bloqueados y los puntos totales del usuario.

📱 PWA 1 RF

▾
RF32El sistema debe ser instalable como app en PC, Android e iPhone, funcionando parcialmente offline con Service Worker y usando un manifiesto dinámico para evitar bloqueos en hostings.

⭐ Premium 2 RF

▾
RF33El sistema debe mostrar los planes disponibles (Registrado vs Premium) y permitir el pago simulado con tarjeta, PSE, Nequi o Daviplata.
RF34El sistema debe actualizar el rol del usuario a Premium después del pago y desbloquear las funciones avanzadas.

🤖 Chatbot IA 2 RF

▾
RF35El sistema debe ofrecer un chatbot que responda preguntas financieras, personalice las respuestas según los datos reales del usuario, haga proyecciones y dé recomendaciones de inversión según su perfil de riesgo.
RF36El sistema debe detectar intenciones sin depender de tildes ni mayúsculas, y explicar cómo funciona cada módulo del sistema.

🏔️ Simulador de Deudas 1 RF

▾
RF37El sistema debe simular las estrategias "avalancha" (mayor tasa primero) y "bola de nieve" (menor saldo primero), comparar ambas y recomendar la mejor, mostrando gráficas de evolución del saldo.

💰 Simulador de Inversiones 2 RF

▾
RF38El sistema debe calcular el rendimiento de CDT, FIC y cuenta de ahorros, comparar los tres productos y calcular el rendimiento real (descontando inflación y retención).
RF39El sistema debe calcular el aporte mensual necesario para alcanzar una meta y permitir personalizar la tasa de interés.

💡 Ideas de Inversión 1 RF

▾
RF40El sistema debe mostrar todas las opciones de inversión intangible ordenadas por perfil de riesgo (marcando la recomendada con justificación) y productos tangibles con cálculo exacto de rentabilidad según el presupuesto del usuario.

⚙️ Configuración 1 RF

▾
RF41El sistema debe permitir editar las tasas del mercado (usura, inflación, CDT) y actualizar las proyecciones cuando cambian las tasas.

🔐 Seguridad 2 RF

▾
RF42El sistema debe proteger todos los formularios con tokens CSRF, usar consultas preparadas (PDO) para prevenir inyección SQL y validar la pertenencia de datos (categoría, cuenta) al usuario.
RF43El sistema debe expirar las sesiones después de 30 minutos de inactividad y registrar los intentos fallidos de login.

⚡ Rendimiento 4 RNF

▾
RNF01El sistema debe cargar cualquier página en menos de 2 segundos en condiciones normales de red.
RNF02El sistema debe soportar hasta 100 usuarios concurrentes sin degradar el rendimiento.
RNF03Las consultas a la base de datos deben ejecutarse en menos de 500 ms para el 95% de las peticiones.
RNF04El sistema debe procesar la importación de archivos CSV de hasta 5 MB en menos de 10 segundos.

🔒 Seguridad 5 RNF

▾
RNF05Todas las contraseñas deben almacenarse cifradas con bcrypt (mínimo 10 rondas).
RNF06Todas las comunicaciones deben usar HTTPS/TLS 1.2 o superior en producción.
RNF07El sistema debe cumplir con el estándar OWASP Top 10 para prevenir vulnerabilidades comunes.
RNF08Las sesiones deben expirar después de 30 minutos de inactividad y usar tokens seguros.
RNF09El sistema debe cumplir con la normativa GDPR para protección de datos personales.

🎨 Usabilidad 5 RNF

▾
RNF10La interfaz debe cumplir con los estándares de accesibilidad WCAG 2.1 nivel AA.
RNF11El diseño debe ser responsive y adaptarse a dispositivos desde 320px hasta 4K.
RNF12El sistema debe ofrecer modo oscuro y claro, con persistencia de la preferencia del usuario.
RNF13Los mensajes de error deben ser claros y en español, indicando cómo solucionar el problema.
RNF14El sistema debe incluir un centro de ayuda con documentación de cada módulo y un chatbot de soporte.

🌐 Compatibilidad 3 RNF

▾
RNF15El sistema debe ser compatible con Chrome, Firefox, Edge y Safari en sus últimas versiones.
RNF16El sistema debe funcionar en Windows, macOS, Linux, Android e iOS.
RNF17El sistema debe ser instalable como PWA en PC, Android e iPhone.

🔧 Mantenibilidad 3 RNF

▾
RNF18El código debe seguir el patrón MVC para facilitar el mantenimiento y la escalabilidad.
RNF19El código debe estar documentado con comentarios y seguir estándares de codificación PSR-12.
RNF20El sistema debe usar control de versiones con Git y tener un repositorio en GitHub.

📡 Disponibilidad 3 RNF

▾
RNF21El sistema debe tener una disponibilidad mínima del 99% en producción.
RNF22El sistema debe funcionar parcialmente offline gracias al Service Worker de la PWA.
RNF23El sistema debe tener respaldos automáticos de la base de datos al menos una vez al día.

📈 Escalabilidad 2 RNF

▾
RNF24La arquitectura debe permitir agregar nuevos módulos sin afectar los existentes.
RNF25El sistema debe poder migrar de un hosting compartido a un servidor dedicado sin cambios en el código.
